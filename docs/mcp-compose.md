# MCP: агент собирает цепочку, повторяется вся цепочка

Новый инструмент `compose_pipeline` доступен через существующий `wedra mcp` (stdio). Это инструмент для подключённого LLM-агента, а не встроенная модель: сам бинарник не придумывает плагины по текстовому запросу.

## Работа агента

1. `list_plugins`: найти установленные плагины.
2. `describe_plugin`: узнать реальные входы, выходы, типы и permissions.
3. `compose_pipeline`: передать имя, input, stages, every_minutes и timeout. Агент сам выбирает плагины и прописывает bind по их контрактам.
4. Если ok=false, исправить issues; при необходимости использовать `plan_pipeline` с возвращённым yaml.
5. Повторить с save=true для сохранения артефактов. Новое имя для каждой редакции: существующие файлы не перезаписываются.

До **256 шагов**, до **32 параллельных шагов на этап**. 15 плагинов — обычный размер. Этапы последовательны, шаги внутри одного этапа параллельны. Между этапами барьер: следующий начинается после завершения всех шагов предыдущего. Это staged parallelism, не произвольный DAG из независимо продвигающихся веток. Плагины одного этапа не должны зависеть от результатов друг друга.

Пример формы вызова (имена плагинов и bind заменяются реальными из describe_plugin):

```json
{
  "name": "parser_bundle_v1",
  "every_minutes": 7,
  "timeout": "20m",
  "input": {},
  "stages": [
    {"steps": [
      {"id": "source_a", "plugin": "REAL_SOURCE_A"},
      {"id": "source_b", "plugin": "REAL_SOURCE_B"}
    ]},
    {"steps": [
      {"id": "process_a", "plugin": "REAL_PROCESS_A", "bind": {"REAL_INPUT_PORT": "steps.source_a.REAL_OUTPUT_PORT"}},
      {"id": "process_b", "plugin": "REAL_PROCESS_B", "bind": {"REAL_INPUT_PORT": "steps.source_b.REAL_OUTPUT_PORT"}}
    ]},
    {"steps": [{"id": "finish", "plugin": "REAL_FINISH"}]}
  ],
  "save": true
}
```

Для 15 плагинов можно сделать пять этапов по три плагина. Эта форма примера не исполняема без реальных плагинов.

## Результат и включение расписания

Возвращаются `ok`, `issues`, `yaml`, `step_count`, `stage_count`, `activated:false`. При успешной проверке также `fleet_yaml`. При save=true — `pipeline_path` и `fleet_path` в workdir MCP. Генерация проверяет существующими механизмами синтаксис, контракты плагинов и политику MCP; код не запускается.

Файлы: `<name>.pipeline.yaml` и `<name>.fleet.yaml`. Запуск из того же рабочего каталога:

```bash
wedra fleet --config=parser_bundle_v1.fleet.yaml --check
wedra fleet --config=parser_bundle_v1.fleet.yaml
```

Перед запуском настройте WEDRA_TRIGGER_TOKEN, Telegram и/или HTTP-webhook по FORK-UBUNTU.md. В systemd рабочий каталог `/var/lib/wedra`: MCP должен сохранять туда либо оператор переносит файлы и исправляет пути. Для нескольких цепочек **объедините jobs в один fleet.yaml** существующей службы и перезапустите её. Не запускайте отдельные демоны с одним и тем же runs_dir/портом.

`every: 7m` повторяет всю цепочку с интервалом 7 минут. Первый запуск через секунду после старта демона, дальше интервалы от момента планирования, а не от завершения. Работающий прогон не перекрывается: новые задания ждут в дисковой очереди; повторные расписания объединяются, если для job уже есть ожидающее задание. См. fleet-reliability.md. Нельзя одновременно задать cron и every. Интервалы >=1m, включая 90m. Контрольная точка интервала сохраняется между рестартами; пропущенные интервалы не воспроизводятся пачкой.

Алерты — success/failure/timeout всей цепочки через уже настроенные каналы fleet. Это не алерты на каждый из 15 шагов. Таймаут общий на прогон.

## Граница полномочий

Генерация НЕ активирует службу, НЕ изменяет активный конфиг, НЕ устанавливает плагины и НЕ выставляет auto_approve=true. Требуется один раз проверить и включить расписание оператором; затем повторы автоматические. Для плагинов с опасными правами сохраняйте обязательные человеческие гейты и политику доверия. Конфиг с auto_approve:false сам гейты не одобряет — без человека такие цепочки могут завершиться ошибкой/таймаутом. Превращать всё в безусловное --yes агент не может.

Пример задания агенту:

> Найди установленные плагины, собери цепочку из 15 шагов с параллельными этапами, повтор всей цепочки каждые 7 минут, таймаут 20 минут. Проверь порты через describe_plugin, исправь issues, сохрани артефакты через compose_pipeline. Не включай автоодобрение, не меняй активный конфиг. Покажи мне план и путь к fleet YAML для включения.
